# Prepare and publish polix 0.1.0 for public use, with Claude Code as the only supported agent

## Overview

Polix gets its first public release, 0.1.0, so anyone can install it and set up the basic guardrails of a repository.
Before tagging it, the project stops presenting itself as an internal proof of concept and tells a newcomer, in one
sentence, what it is: declarative guardrails for Claude Code.

Codex support is not implemented: an adapter exists but it was never tried against a running Codex.
From this release the install sets up only Claude Code, Codex is reached only on explicit request, and every doc,
help text and diagram says plainly that Codex is not implemented.

The README is rewritten to convert: the positioning sentence at the top, a short animated demo of polix blocking a
force push and an edit of `.env`, a ten line `guardrails:` quick start, and an honest status of what 0.1.0 does and
does not do.
The repository gains a changelog with the 0.1.0 entry and a contributing guide, the internal references to Logalty
leave the public docs, and the agent fragment for governed repositories is written in English.

The last step is the publication itself, run by a person once the change is on main: the tag, the release built by
CI, the description and topics of the GitHub repository, and a check that the one-line installers work.

## Context

The repository is public at `mlophez/polix-ai` and has a working release pipeline, but no release exists yet.
The docs still say "proof of concept", point to internal Logalty material and present Codex as a supported agent,
while `polix install` registers Codex by itself whenever it finds it.
The outcome is a tagged 0.1.0 whose docs let a stranger install polix and write the basic guardrails without help.

## Decisions

- Codex stays in the code but becomes opt-in: `polix install` sets up only Claude Code unless `--agent codex` is
  passed, and the docs, the help and the output say Codex support is not implemented and untested.
- `polix doctor` checks Codex only when polix is already registered for it (a hooks file of Codex that runs polix, or
  the plugin enabled in `~/.codex/config.toml`), so a Codex user who never opted in gets no Codex findings.
- The notion "Codex is used here" (`CodexUsed`) disappears from install and doctor, since nothing decides on it any
  more; `polix uninstall` and `polix update` keep removing and refreshing the Codex parts they find.
- The runtime of `polix hook codex` does not change; only its help text marks it as not implemented.
- The positioning sentence, repeated in the README, the root help and the GitHub description: "Declarative guardrails
  for Claude Code: one polix.yaml decides what the agent may not touch, what must pass and what runs at every step."
- Stability wording replaces "proof of concept": 0.1.0 is the first public release, `polix.yaml` is `version: 1`, and
  a 0.x release may still change the format, which `requires:` lets a repository pin.
- The demo is a synthetic recording made with vhs from a tape kept in the repository: real `polix hook claude` calls
  fed with recorded hook inputs, not a recorded Claude Code session.
- New project files: `CHANGELOG.md` and `CONTRIBUTING.md`; no `SECURITY.md` and no issue templates in this release.
- Internal references to Logalty (Logalty Control, the artifact "Dispatcher de workflows", "the current Logalty flow")
  are removed from every public file; the files under `ai/` are not public docs and stay as they are.
- The publication is the last task, run by a person after the change is merged, since it pushes a tag and edits
  the public repository.
- Assumption: the version examples that show a future release (`requires: 0.2.0`, `just release 0.2.0`) stay as
  they are; they illustrate a later release, not the current one.
- Assumption: the release notes stay generated by GitHub (`--generate-notes`); `CHANGELOG.md` is the curated record.

## Approach

Install (`internal/setup`, use case InstallSetup): the logic `InstallSetup` loses its `codexUsed` parameter and
defaults to Claude Code alone; the port `InstallSetupPort` loses `CodexUsed`, and `InstallSetupAdapter` with it.
When the agents asked include Codex, the shell prints one extra line saying Codex support is not implemented and
untested in this release.
The help of `--agent` and the long help of `polix install` state the new default.

Doctor (`internal/setup`, use case DiagnoseSetup): `diagnoseSetupCodex` decides from the files the shell already
reads (the Codex hooks files and `~/.codex/config.toml`) whether polix is registered for Codex.
Not registered: no finding.
Registered: the existing checks, and the OK line says Codex is not implemented and untested.
The field `CodexUsed` leaves the domain struct `Inspection` (`internal/setup/setup_finding.go`), the port
`DiagnoseSetupPort` and `DiagnoseSetupAdapter`.

Help texts: `AnswerHookCommand` marks the agent `codex` as not implemented, and the root command of `cmd/polix`
carries the positioning sentence and names Claude Code as the supported agent.

Docs, examples and plugin texts follow the decisions above; the README is rewritten last, once the demo, the
changelog, the contributing guide and the renamed section of known limits exist, so its links resolve.

No contract of `polix.yaml`, no event and no hook input changes.
The only command line change is the default of `polix install --agent`.

### Discarded alternatives

- Docs only, leaving the install as it is: a Codex user would get an untested setup without asking for it.
- Removing Codex from the binary: a large change to `internal/agent` and `internal/setup` for no gain in 0.1.0.
- A recorded Claude Code session as the demo: an executor cannot reproduce it, and it would drift with every
  version of Claude Code.

## Acceptance criteria

- AC1: `polix install` without `--agent` sets up only Claude Code, even when Codex is on the `PATH` or configured;
  with `--agent codex` it still writes `.codex/hooks.json` and enables the plugin, and prints that Codex support is
  not implemented and untested.
- AC2: `polix doctor` reports no Codex finding unless polix is registered for Codex; when it is, its checks run and
  its OK line says Codex is not implemented and untested.
- AC3: the help of `polix`, `polix hook` and `polix install` names Claude Code as the supported agent and marks Codex
  as not implemented.
- AC4: `rg -i "proof of concept|Logalty|Dispatcher de"` finds nothing in `README.md`, `CHANGELOG.md`,
  `CONTRIBUTING.md`, `docs/`, `examples/`, `plugins/`, `cmd/`, `internal/`, `install.sh` and `install.ps1`.
- AC5: `README.md`, `docs/polix.md`, `docs/architecture.md`, `CHANGELOG.md` and `docs/assets/overview.svg` say that
  Codex is not implemented, and none of them presents Codex as supported.
- AC6: the README opens with the positioning sentence, shows the demo GIF, has a quick start whose `guardrails:`
  fits in about ten lines, lists every command `polix --help` lists, and its status section describes 0.1.0 and
  matches the skills and agents the plugin ships.
- AC7: `just demo` rebuilds `docs/assets/demo.gif` from `docs/assets/demo/demo.tape`; the recording shows a
  forbidden force push blocked with its reason, an edit of `.env` blocked, and an allowed command let through.
- AC8: `CHANGELOG.md` holds a 0.1.0 entry (what the release brings and its known limits, Codex among them), and
  `CONTRIBUTING.md` explains how to build, test and check the repository and how its own polix governs it.
- AC9: `examples/AGENTS-polix.md` is in English, and `examples/polix.yaml` and
  `plugins/polix/skills/workflow/reference.yaml` stay byte-for-byte equal.
- AC10: the GitHub release `v0.1.0` exists with the six binaries, `install.sh`, `install.ps1` and `checksums.txt`,
  the install jobs of the release workflow pass on the three systems, and the repository description is the
  positioning sentence.
- AC11: `just test`, `golangci-lint run ./...`, `just check` and `claude plugin validate plugins/polix` pass.

## Out of scope

- Launch channels and content of `ai/tasks/open-source-launch.md` (communities, Show HN, posts, meetup): they are
  not changes to the repository.
- `SECURITY.md`, issue and pull request templates, and signed releases: not chosen for this release.
